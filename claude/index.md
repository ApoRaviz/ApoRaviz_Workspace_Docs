# Claude Code — คู่มือคำสั่งและความสามารถ (ฉบับละเอียด)

หน้านี้คือคู่มือที่ Claude เขียนอธิบายตัวเอง สำหรับเปิดอ่านเวลาทำงานกับ AI ใน workspace `ApoRaviz` — แยกหมวดชัด บอกวิธีใช้และว่าเหมาะกับงานแบบไหน

> เป็น snapshot — รายการจริงต่างกันได้ตามเวอร์ชัน **แหล่งความจริงคือพิมพ์ `/help` ในเครื่องคุณเอง**

## ภาพจำ — มี 3 ชั้น อย่าสับสน

```text
slash command (/xxx) = "คุณ" พิมพ์เอง สั่งตัวโปรแกรม Claude Code
skill                = ความสามารถเฉพาะทาง ที่ Claude เรียกได้ (บางตัวคุณพิมพ์ /ชื่อ เรียกเองก็ได้)
tool                 = ความสามารถพื้นฐานของ Claude เช่น อ่าน/แก้ไฟล์ รัน command
```

**สิ่งที่คนเข้าใจผิดบ่อยที่สุด:** สแลชคอมมานด์ส่วนใหญ่ Claude กดเองไม่ได้ — คุณเป็นคนพิมพ์ ตัวโมเดลสั่ง `/clear`, `/compact`, `/cost`, `/model` ให้ตัวเองไม่ได้

# หมวด A — Slash Commands (คุณพิมพ์ใน CLI)

## A1. จัดการ session / context

### `/clear`
- **ทำอะไร:** ล้างบทสนทนาทั้งหมด เริ่มใหม่จาก context ว่าง
- **ใช้ยังไง:** พิมพ์ `/clear`
- **เหมาะกับ:** ขึ้นงาน/หัวข้อใหม่ที่ไม่เกี่ยวกับของเดิมเลย อยากได้ context สะอาด ไม่ให้เรื่องเก่ากวน

### `/compact`
- **ทำอะไร:** บีบอัดบทสนทนาให้สั้นลง แต่เก็บบริบทสำคัญไว้ (สรุปของเก่า)
- **ใช้ยังไง:** `/compact` หรือใส่โฟกัสได้ เช่น `/compact เก็บเรื่อง roadmap review ไว้`
- **เหมาะกับ:** แชทยาวจน **context ใกล้เต็ม** แต่ยังทำงานเดิมต่อ ไม่อยากเริ่มใหม่

### `/resume`
- **ทำอะไร:** กลับเข้าเซสชัน/บทสนทนาก่อนหน้าที่เคยทำค้างไว้
- **ใช้ยังไง:** `/resume` แล้วเลือกจากรายการ
- **เหมาะกับ:** เปิดเครื่องมาทำงานต่อจากเมื่อวาน

## A2. โปรเจกต์ & memory

### `/init`
- **ทำอะไร:** ให้ Claude สำรวจโครงสร้าง repo แล้วสร้างไฟล์ `CLAUDE.md` เป็น "แผนที่โปรเจกต์"
- **ใช้ยังไง:** `cd` เข้า repo แล้วพิมพ์ `/init`
- **เหมาะกับ:** repo ใหม่ที่ยังไม่มี `CLAUDE.md` อยากให้ AI เข้าใจบริบทตั้งแต่แรก

### `/memory`
- **ทำอะไร:** เปิดดู/แก้สิ่งที่ Claude จำข้ามเซสชัน (memory files + `CLAUDE.md`)
- **ใช้ยังไง:** `/memory` แล้วเลือกไฟล์ที่จะแก้
- **เหมาะกับ:** อยากเพิ่ม/ลบ/แก้ preference เอง เช่น กติกาการทำงาน สิ่งที่ให้จำไว้

### `/config`
- **ทำอะไร:** เปิดหน้าตั้งค่า (theme, โมเดล default, ฯลฯ)
- **ใช้ยังไง:** `/config`
- **เหมาะกับ:** ปรับ preference เบา ๆ ของ CLI

## A3. โมเดล & ต้นทุน

### `/model`
- **ทำอะไร:** สลับโมเดล AI กลางคัน
- **ใช้ยังไง:** `/model` เลือกจากเมนู หรือระบุ เช่น `/model opus`, `/model sonnet`
- **เหมาะกับ:** งาน design/รีวิวซับซ้อน → Opus; งานเล็ก/ตอบเร็ว → รุ่นเบากว่า เพื่อประหยัดเวลา/ต้นทุน

### `/cost`
- **ทำอะไร:** แสดง token และค่าใช้จ่ายของเซสชันนี้
- **ใช้ยังไง:** `/cost`
- **เหมาะกับ:** เช็คว่าคุยยาวไปกิน token เท่าไหร่ ก่อนตัดสินใจ `/compact` หรือ `/clear`

## A4. รีวิว & คุณภาพ

### `/review`
- **ทำอะไร:** รีวิว **GitHub Pull Request** แบบ code review จริง
- **ใช้ยังไง:** `/review` (ในบริบท PR) — ต่างจาก `/code-review` ที่รีวิว diff ในเครื่อง (ดูหมวด B)
- **เหมาะกับ:** มี PR บน GitHub อยากได้ความเห็นเชิงลึกก่อน merge

## A5. ระบบ & แก้ปัญหา

### `/help`
- **ทำอะไร:** แสดงคำสั่งทั้งหมด — **แหล่งความจริงของเวอร์ชันคุณ**
- **ใช้ยังไง:** `/help`
- **เหมาะกับ:** ไม่แน่ใจว่ามีคำสั่งอะไรบ้าง เช็คอันนี้ก่อนเสมอ

### `/agents`
- **ทำอะไร:** จัดการ subagent (สร้าง/ดู/แก้ agent เฉพาะทาง)
- **ใช้ยังไง:** `/agents`
- **เหมาะกับ:** อยากตั้ง agent เฉพาะงาน เช่น reviewer, explorer

### `/permissions`
- **ทำอะไร:** ดู/แก้สิทธิ์ที่อนุญาตให้ Claude ทำ (เช่น รัน command ไหนได้เลยไม่ต้องถาม)
- **ใช้ยังไง:** `/permissions`
- **เหมาะกับ:** ลดการถาม permission ซ้ำ ๆ กับคำสั่งที่ไว้ใจแล้ว

### `/doctor`
- **ทำอะไร:** ตรวจสุขภาพการติดตั้ง Claude Code รวมทีเดียว
- **ใช้ยังไง:** `/doctor`
- **เหมาะกับ:** CLI มีปัญหาแปลก ๆ อยากรู้ว่าติดตรงไหน

### `/bug`
- **ทำอะไร:** รายงานบั๊กของ Claude Code กลับทีม Anthropic
- **ใช้ยังไง:** `/bug` แล้วอธิบายอาการ
- **เหมาะกับ:** เจอพฤติกรรมผิดปกติของตัว CLI เอง

# หมวด B — Skills (Claude เรียกได้)

skill = ความสามารถเฉพาะทาง Claude เลือกเรียกเองได้ หรือคุณพิมพ์ `/ชื่อ-skill` เรียกก็ได้ ชุดที่มีในเซสชันของเรา:

## B1. คุณภาพโค้ด & รีวิว

### `code-review`
- **ทำอะไร:** รีวิว diff ปัจจุบันหา bug + จุด simplify/ประสิทธิภาพ
- **ใช้ยังไง:** `/code-review` หรือระบุระดับ `/code-review high` (low/medium = น้อยแต่ชัวร์, high→max = กว้างขึ้น, `ultra` = multi-agent บน cloud), เติม `--fix` ให้แก้ให้เลย
- **เหมาะกับ:** ก่อน commit/push อยากให้ตรวจ diff เชิงลึก

### `security-review`
- **ทำอะไร:** ตรวจช่องโหว่ความปลอดภัยของ diff บน branch
- **ใช้ยังไง:** `/security-review`
- **เหมาะกับ:** งานที่แตะ auth, input, secret, endpoint — ตรงกับ Phase 1.6 ของเรา

### `review`
- **ทำอะไร:** รีวิว GitHub PR (เหมือน `/review`)
- **เหมาะกับ:** ตรวจ PR ของคนอื่น/ของเราบน GitHub

### `simplify`
- **ทำอะไร:** ปรับ code ที่แก้ให้กระชับ/ใช้ซ้ำได้ (เน้นคุณภาพ **ไม่ล่า bug**)
- **ใช้ยังไง:** `/simplify`
- **เหมาะกับ:** โค้ดทำงานได้แล้วแต่รก อยากเกลาให้อ่านง่าย

## B2. รันจริง & ยืนยัน

### `run`
- **ทำอะไร:** เปิด/รันแอปของโปรเจกต์เพื่อดูผลจริง
- **ใช้ยังไง:** `/run`
- **เหมาะกับ:** อยากเห็นแอปทำงานจริง ไม่ใช่แค่ผ่าน test

### `verify`
- **ทำอะไร:** รันแอปจริงแล้วสังเกตพฤติกรรม เพื่อยืนยันว่าการแก้ได้ผลตามตั้งใจ
- **ใช้ยังไง:** `/verify`
- **เหมาะกับ:** ยืนยัน fix/feature ก่อนปิดงานหรือก่อน push

## B3. อัตโนมัติ & ตั้งเวลา

### `loop`
- **ทำอะไร:** รัน prompt/คำสั่งซ้ำเป็นรอบ ๆ
- **ใช้ยังไง:** `/loop 5m /code-review` (ทุก 5 นาที) หรือ `/loop <prompt>` ให้ Claude กำหนดจังหวะเอง
- **เหมาะกับ:** งาน poll สถานะ, เฝ้า CI, ทำซ้ำเป็นระยะ

### `schedule`
- **ทำอะไร:** ตั้ง cloud agent ให้รันตาม cron
- **ใช้ยังไง:** `/schedule`
- **เหมาะกับ:** งานประจำที่อยากให้รันเองแม้ไม่ได้เปิดเครื่อง

## B4. ตั้งค่า & อ้างอิง

### `update-config`
- **ทำอะไร:** แก้ `settings.json` (permission, hook, env var)
- **ใช้ยังไง:** `/update-config` เช่น "อนุญาต npm commands", "when Claude stops แสดง X"
- **เหมาะกับ:** ตั้ง automation ("ทุกครั้งที่ X ให้ทำ Y" ต้องใช้ hook), จัดการ permission

### `keybindings-help`
- **ทำอะไร:** ปรับคีย์ลัดของ Claude Code
- **เหมาะกับ:** อยากเปลี่ยน shortcut, ตั้ง chord binding

### `claude-api`
- **ทำอะไร:** อ้างอิง Claude API / SDK (model id, ราคา, tool use, streaming, caching)
- **เหมาะกับ:** ตอนสร้างแอปที่เรียก Claude API (Phase 2 ของเรา)

## B5. งานภาพ / ดีไซน์

### `dataviz`
- **ทำอะไร:** แนวทางทำ chart/กราф/dashboard ให้อ่านง่ายและสีถูกหลัก
- **เหมาะกับ:** ก่อนทำ visualization ใด ๆ

### `artifact-design`
- **ทำอะไร:** หลักการออกแบบ Artifact (หน้าเว็บที่ทำให้เปิดดูบน claude.ai)
- **เหมาะกับ:** ตอนจะทำรายงาน/หน้าเว็บสวย ๆ ให้ดู

# หมวด C — Tools (ความสามารถพื้นฐานของผม)

สิ่งที่ผมเลือกใช้เองตามงาน ไม่ต้องมีคำสั่งพิเศษ:

| ความสามารถ | ทำอะไร | เหมาะกับ |
|---|---|---|
| อ่าน/ค้นไฟล์ | เปิดไฟล์, ค้น keyword ทั่ว repo, ดูโครงสร้าง | สำรวจ code ก่อนแก้ |
| แก้/สร้างไฟล์ | แก้เฉพาะจุด หรือเขียนไฟล์ใหม่ | ลงมือแก้จริง |
| รัน command | `git`, `npm`, build, test ผ่าน terminal | verify, build, ตรวจสถานะจริง |
| เว็บ | ค้น/เปิดหน้าเว็บ | หาข้อมูลล่าสุด, อ่าน docs |
| subagent | แตกงานย่อยให้ agent อื่นทำคู่กัน | งานค้นหากว้าง ๆ หลายจุดพร้อมกัน |
| memory | จำ preference ข้ามเซสชัน | จำกติกา เช่น "review ผ่าน = stamp เลย" |
| artifact | ทำหน้าเว็บ/รายงานให้เปิดดู | สรุปงานแบบ visual |

# หมวด D — ผมทำงานยังไง (ศึกษาตัวเอง)

- **ตัดสินใจเลือก tool เอง:** อ่านไฟล์ก่อนแก้เสมอ, งานที่ไม่พึ่งกันผมยิงหลาย tool พร้อมกันเพื่อให้เร็ว
- **รีวิว Learning Loop (กติกา 2.4):** ผม **ไม่ได้ใช้ `/review`** — ผมอ่าน draft ของ Codex + verify กับ repo จริง (รัน git/build) + เทียบกับ TEACHING_RULES แล้วค่อยตัดสินผ่าน/ไม่ผ่าน
- **ขออนุญาตก่อนงานที่ย้อนยาก/ออกนอก:** push, ลบไฟล์, ส่งข้อมูลออกภายนอก ผมยืนยันก่อนเสมอ (งานอ่าน/แก้ในเครื่องทำได้เลยตาม permission)
- **บทบาทในโปรเจกต์นี้:** ผม = Designer/Reviewer, Codex = Hands-on Tutor — ใน `_docs` ผมเป็น Reviewer/QA ของ Knowledge Sync
- **ข้อจำกัด:** สั่งสแลชคอมมานด์ให้ตัวเองไม่ได้, ไม่รัน `/code-review ultra` เอง (บิลแยก คุณสั่ง), ไม่เห็นสิ่งที่อยู่นอก repo/เครื่องนี้ นอกจากค้นเว็บ
